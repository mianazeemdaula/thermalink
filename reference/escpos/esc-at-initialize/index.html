ESC @ (1B 40): initialize the printer

Two bytes, 1B 40, that put the printer back to its power-on text settings. Send them at the start of every job so styles left over from the last receipt do not leak into this one.

ASCIIESC @
Hex1B 40
Decimal27 64

Parameters

No parameters.

What it does

It resets the settings that live in the printer's working memory: bold, underline, character size, white-on-black, alignment, line spacing, left margin and print width, tab stops and the selected code page. Thermalink sends it as the first two bytes of every job.

python-escpos describes it as "Clear data in buffer and reset modes". The buffer part matters: text you sent without a line feed after it has not been printed yet, and ESC @ discards it. The viewer warns when that happens.

It does not touch settings stored in the printer's non-volatile memory (memory switches, DIP switches, default code page). My BIXOLON SRP-352plusIII has its double-byte (Chinese) mode switched on in its memory switches, and ESC @ at the start of the job did not turn it off: every byte above 0x80 still printed as a Chinese character.

Example

Bold is on, one line prints, then ESC @ resets it.

1B 45 01 42 6F 6C 64 20 6C 65 66 74 20 6F 76 65 72 0A 1B 40 41 66 74 65 72 20 45 53 43 20 40 3A 20 6E 6F 72 6D 61 6C 0A

Sending it from code

JavaScript (bytes)

const init = new Uint8Array([0x1b, 0x40]);

PHP with escpos-php

$printer->initialize(); // writes 1B 40

Python (raw bytes)

data = b"\x1b\x40" + data

Common mistakes

  • Sending ESC @ in the middle of a job after text with no LF. That text is thrown away.
  • Expecting it to fix the code page or Kanji mode set in the printer's memory switches. It only resets runtime settings; check the self-test page instead.
  • Leaving it out because "the printer was just switched on". The previous job may have left bold or a different code page selected.

Related commands
