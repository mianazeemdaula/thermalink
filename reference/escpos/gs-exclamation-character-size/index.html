ESC/POS command reference › GS !

GS ! (1D 21): double width and height text, up to 8x

One byte n sets both multipliers: the high four bits are width minus 1, the low four bits are height minus 1. 1D 21 11 is double width and double height.

ASCIIGS ! n
Hex1D 21 n
Decimal29 33 n

Parameters

n(width - 1) × 16 + (height - 1), width and height 1 to 8. 0x00 normal, 0x01 double height, 0x10 double width, 0x11 both, 0x22 triple, 0x77 eight times.

What it does

escpos-php's setTextSize($w, $h) computes 16 × (w - 1) + (h - 1) and checks each multiplier is 1 to 8. python-escpos builds the same byte from width values 0x00 to 0x70 and height values 0x00 to 0x07.

Wider text means fewer characters per line. Font A is 12 dots wide, so an 80 mm printer with 576 printable dots fits 48 characters at normal width, 24 at double width and 16 at triple width.

Thermalink uses GS ! for headings. The size stays in force until another GS !, ESC @ or ESC !.

Example

Double width and height, normal, then double height only.

1B 61 01 1D 21 11 43 41 46 45 0A 1D 21 00 6E 6F 72 6D 61 6C 20 73 69 7A 65 0A 1D 21 01 74 61 6C 6C 20 6F 6E 6C 79 0A 1D 21 00

Sending it from code

JavaScript (bytes)

const size = (w, h) => [0x1d, 0x21, ((w - 1) << 4) | (h - 1)];
size(2, 2); // [0x1d, 0x21, 0x11]

PHP with escpos-php

$printer->setTextSize(2, 2); // 1D 21 11
$printer->setTextSize(1, 1); // 1D 21 00

Python (raw bytes)

def size(w, h):
    return bytes([0x1d, 0x21, ((w - 1) << 4) | (h - 1)])

Common mistakes

  • Writing the multiplier in decimal. GS ! 2 is not double size: 0x02 means normal width and triple height. Double both is 0x11 (decimal 17).
  • Keeping the same column layout after enlarging text. Halve the characters per line at double width, or the line wraps.
  • Forgetting to send GS ! 0 after the heading.
