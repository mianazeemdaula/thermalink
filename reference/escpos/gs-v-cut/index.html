GS V (1D 56): cut the paper (full or partial)

1D 56 00 is a full cut, 1D 56 01 a partial cut. 1D 56 41 n and 1D 56 42 n feed to the cutter first, then cut.

ASCIIGS V m [n]
Hex1D 56 m [n]
Decimal29 86 m [n]

Parameters

m0 or 48 = full cut, 1 or 49 = partial cut at the current position. 65 = feed, then full cut; 66 = feed, then partial cut.
nonly for m = 65 or 66: extra feed before the cut, 0 to 255 units.

What it does

A partial cut leaves a small strip uncut, so the receipt hangs from the printer instead of dropping. A full cut separates it.

The cutter sits a little past the print head, so a cut straight after the last line goes through that line. Feed first (Thermalink sends ESC d 3 then GS V 0 or GS V 1), or use m = 65 or 66, which feed to the cutting position themselves.

Libraries pick different forms: python-escpos sends 1D 56 00 / 1D 56 01; escpos-php's cut() sends 1D 56 41 03 (full) or 1D 56 42 03 (partial) by default.

Example

Feed three lines, partial cut, then the next receipt starts.

4C 61 73 74 20 6C 69 6E 65 0A 1B 64 03 1D 56 01 4E 65 78 74 20 72 65 63 65 69 70 74 0A

Sending it from code

JavaScript (bytes)

const fullCut = [0x1b, 0x64, 3, 0x1d, 0x56, 0];
const feedAndPartialCut = [0x1d, 0x56, 66, 0];

PHP with escpos-php

$printer->cut();                     // 1D 56 41 03
$printer->cut(Printer::CUT_PARTIAL); // 1D 56 42 03

Python (raw bytes)

data += b"\x1b\x64\x03\x1d\x56\x00"  # feed 3 lines, full cut

Common mistakes

  • Cutting through the last line because there was no feed before GS V 0.
  • Debugging the bytes on a printer that has no cutter. Check the model has one first.
  • Mixing up 0x41 and 0x01: 1D 56 41 needs one more byte (n) after it, or the printer takes your next byte as n.
