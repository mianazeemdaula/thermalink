ESC/POS viewer: see what your receipt printer will print

Paste the bytes your app sends to a thermal printer, as hex, base64 or \x1b-style text, or drop a .bin file. You get a picture of the receipt, every command decoded, and warnings for the usual mistakes. It all runs in your browser and the bytes never leave this page.

    How to get the bytes out of your app

    Print to a file instead of the printer, then drop that file here.

    • escpos-php: use new FilePrintConnector("receipt.bin") instead of the Windows or network connector.
    • python-escpos: print to escpos.printer.Dummy(), then save p.output to a file.
    • Node / JavaScript: whatever library you use ends up with a Buffer or Uint8Array. Write it to disk, or log it as hex and paste it here.
    • Windows: install the "Generic / Text Only" driver on the FILE: port and print to it. The file contains exactly what the app sent.

    Mistakes it points out

    • UTF-8 text sent to the printer. Receipt printers use one-byte code pages, so "Café" sent as UTF-8 comes out as "Caf├⌐" on CP437. The viewer spots UTF-8 sequences and shows what the paper will say.
    • Printer in Kanji (double-byte) mode. After FS &, every byte from 0x81 up swallows the next byte and prints as a Chinese or Japanese character. I ran into this on my own BIXOLON, where the mode is set in the printer's memory switches.
    • Lines wider than the paper, barcodes or QR codes too wide to print, and images clipped at the edge.
    • Text left in the buffer with no line feed at the end, and ESC @ throwing away text that was not printed yet.
    • Unknown or cut-off commands, with the byte offset so you can find them.

    What it understands

    Text with fonts A and B, bold, underline, white-on-black, double and up to 8× sizes, alignment, line spacing, margins, tabs, 31 code pages (Epson numbering), Kanji mode, raster images (GS v 0, ESC *, GS ( L), QR codes, CODE128, EAN-13, EAN-8, UPC-A, CODE39 and ITF barcodes with their text, cuts and cash drawer pulses. I checked the QR and barcode drawing against an independent Go library, and the text and image output against what Thermalink sends to a real BIXOLON printer.

    What it cannot show

    • The printer's own font. Letters are drawn with a similar monospace font in the same 12×24 or 9×17 dot cells, so line breaks and widths match, but the letters look a little different on paper.
    • Logos stored inside the printer (FS p, NV graphics), user-defined characters, page mode, PDF417, DataMatrix, Codabar and CODE93. They show as placeholders.
    • Brand differences. Code page numbers for ESC t follow Epson. Some brands number them differently, so if your printer's self-test page says so, pick the right page under "Code page at start". Star printers in Star Line mode use a different command set.

    Your data stays here

    The page is plain HTML and JavaScript. Its content security policy sets connect-src 'none', which stops the browser from sending anything from this page anywhere, so receipts with customer names are safe to paste. The source is in the page; view it to check.
